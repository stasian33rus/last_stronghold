# Матрица классов и форм — статус и очередь разработки (Этап 3+)

Архитектура: **8 классов × 3 формы = 24 `ClassDefinition`-ресурса** в
`resources/classes/` (единый реестр `Classes`, единая боевая логика `PlayerPawn`
— 24 дублирующих класса НЕ создаются). Каждый ресурс имеет слот `model_scene`
для внешней модели `.glb` (назначается в Godot Inspector без правки кода) и
параметры процедурной заглушки (оружие/причёска/цвета/свечение/масштаб).

Легенда статуса:
- **РЕАЛИЗОВАН** — класс доступен в лобби, три формы работают с реальными
  уникальными механиками, покрыт тестами.
- **ДАННЫЕ+ВИЗУАЛ** — ресурс, визуальный слот и цепочка эволюции готовы;
  класс НЕ выбирается в лобби (`implemented=false`): базовый бой и формы
  технически работали бы, но уникальные способности класса ещё не реализованы
  (честный статус заглушки по требованию ТЗ).

Реализованные механики Берсерка (эталон для остальных классов):
- **Форма II «Волна ярости»** (уровень 3): каждые 3 подтверждённых удара —
  ударная волна (радиус 4.5 м, 50% урона, отбрасывание 10) — канон «дальность
  ударной волны, усиленные столкновения»; статы: 150 HP / 30 урона / KB 11.
- **Форма III «Абсолютная ярость»** (уровень 5): добивание целей с HP ≤ 35%
  (×1.6 урона), неистовство при собственных HP < 30% (+25% урона, −25% cooldown
  атаки — канон-пассив «бонусы при потере здоровья»), волна 5.5 м/×0.6/KB 13,
  усиленное отбрасывание (KB 14); статы: 190 HP / 36 урона / быстрые удары.

## Как добавить класс в игру (порядок для каждого из 7)

1. **Способность класса** — новая серверная механика в `PlayerPawn`-хуках или
   отдельном компоненте (по образцу трейтов Берсерка: данные в
   `ClassDefinition`, исполнение на сервере, косметика — событийные RPC).
2. **Формы II/III** — уникальная механика формы в трейт-поля `ClassDefinition`
   (или новые поля при необходимости) + баланс в `.tres`.
3. **`implemented = true`** в форме I — класс появляется в лобби
   (валидация `_sv_set_class` через `Classes.is_selectable`).
4. **Тесты** — smoke-секция по образцу `_test_evolution()` (детерминированная
   проба на peer 777): способность, трейты форм, идемпотентность, репликация.
5. **(Позже) `.glb`-модели** — назначить `model_scene` у трёх форм в Inspector;
   код не меняется (проверено тестом слота `model_scene` в smoke).

## Очередь разработки (рекомендуемый порядок)

Приоритет — классы, не требующие новых подсистем, затем требующие:

1. **Валькирия** — ближний бой: рывок-атака и парирование развивают существующие
   FSM/hitbox-механики (минимальный риск).
2. **Хранительница** — купол/перехват: Area3D-компоненты + модификаторы урона
   (`incoming_damage_multiplier` уже есть); синергия с Этапом 4 (спасение союзников).
3. **Идол** — звуковая волна (AoE-стаггер = `_server_shockwave`-подобие с
   `apply_external_stun`) + командные баффы (инфраструктура командных улучшений
   Гигачада уже есть).
4. **Ведьма** — зоны и притяжение: новая подсистема «зоны» (серверные Area3D с
   тиками) — переиспользуется Алхимиком.
5. **Алхимик** — статусы и реакции: надстройка над зонами Ведьмы.
6. **Снайперша** — дальний бой игрока: серверные снаряды (готовый образец —
   `SpitProjectile` + спавнер арены) + hitscan-пробитие.
7. **Инженер** — сооружения: самая крупная подсистема (турели как серверные
   сущности со спавном через MultiplayerSpawner, лимиты, владение, апгрейды);
   логично делать после дальних снарядов.

Каждый класс — отдельный этап с собственными тестами и отчётом; `implemented`
переключается только когда способности и формы РЕАЛЬНО работают (требование ТЗ:
не объявлять заглушки готовыми).

## Визуальные слоты (24)

Все 24 ресурса имеют `model_scene = null` (проверено smoke) — слоты готовы к
назначению `.glb`. Процедурные заглушки различаются по классам: оружие
(молот/меч/парные клинки/пистолет-ключ/посох/микрофон/винтовка/колба/щит-
рукавица), 7 причёсок, цвета костюма/акцента/волос; формы: I — сдержанный
силуэт, II — сапоги+наплечники+свечение отделки, III — аура-кольцо и парящие
осколки, крупнее силуэт. Замена на `.glb` — одна строка в Inspector на форму.
