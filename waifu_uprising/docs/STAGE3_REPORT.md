# Отчёт: Этап 3 — архитектура 8×3 и система эволюции (вертикальный срез Берсерка)

Дата: 2026-10-23 · Движок: Godot 4.7.2 stable (headless) · База: `2e17625` (аудит + фикс гонки RPC)

## 1. Что сделано

### Шаг A — архитектура 8 классов × 3 формы (24 слота)
- **24 `ClassDefinition`-ресурса** в `resources/classes/`: 8 базовых классов
  (Валькирия, Инженер, Ведьма, Идол, Снайперша, Берсерк, Алхимик, Хранительница —
  канон `GAME_DESIGN.md` §6, id латиницей) × формы I/II/III. Боевая логика едина
  (`PlayerPawn`) — 24 дублирующих класса НЕ создавались.
- **Реестр `Classes`**: базовые формы (лобби) + `all_by_id` (все 24) +
  `get_form_chain/get_form_def/get_next_form` + `is_selectable` (форма I с
  `implemented=true`). Валидация `_sv_set_class` ужесточена: id форм II/III и
  классы-заглушки отклоняются сервером.
- **Визуальные слоты изолированы**: `player_visuals.gd` перестроен в
  данные-драйв конструктор (`rebuild(def)`): 8 типов оружия, 7 причёсок, цвета,
  свечение/масштаб по форме (I — сдержанный, II — сапоги/наплечники/свечение,
  III — аура-кольцо + парящие осколки). Слот `model_scene: PackedScene` на
  каждый из 24 ресурсов — назначение импортированного `.glb` в Godot Inspector
  без правки кода (проверено тестом с подстановочной сценой).
- `player.tscn`: статические меши убраны — визуал строится рантаймом из данных
  формы; боевые компоненты/физика/сеть в сцене не тронуты.
- **Статусы классов честные**: `implemented=true` только у Берсерка; остальные 7 —
  данные+визуал, в лобби не появляются, очередь и требования — `docs/CLASS_MATRIX.md`.

### Шаг B — три формы Берсерка (канон §6.6)
- Форма I «Берсерка» (существующий комплект), форма II «Волна ярости»
  (уровень 3), форма III «Абсолютная ярость» (уровень 5).
- **Реальные игровые отличия (не только цифры)**:
  - II: каждые 3 подтверждённых удара — **ударная волна** (радиус 4.5 м, 50%
    урона, отбрасывание 10) — серверный радиальный урон через штатную
    damage-pipeline (XP-вклад/статистика/награды учитываются);
  - III: **добивание** целей с HP ≤ 35% (×1.6 — хук в HitboxComponent),
    **неистовство** при собственных HP < 30% (+25% урона, −25% cooldown —
    канон-пассив «бонусы при потере здоровья»), волна 5.5 м/×0.6/KB 13 и
    усиленное отбрасывание (KB 14); финальная форма бьёт волной и по
    разрушаемым объектам («разрушает укрытия»);
  - статы: 120/150/190 HP, 26/30/36 урона, темп атаки и рывок растут.
- **Серверная авторитетность**: условие (уровень) проверяет
  `ProgressionSystem._check_evolution` → `PlayerPawn.try_evolve_for_level`
  (идемпотентно, с защитой от скачков и повторных вызовов). Клиентских RPC
  эволюции не существует — клиент не может её запустить.
- **Репликация**: поле `"f"` в снапшоте BodySync; клиент меняет только визуал и
  подпись (статы не пересчитывает). `fx_evolve` (reliable, call_local) — кольца,
  звук `evolve`, анонс «ЭВОЛЮЦИЯ: … → …» на всех пирах; коротко, без кат-сцены.
- **Безопасная замена модели/формы**: узел пешки не пересоздаётся — HP (долечивается
  дельтой максимума, не сбрасывается), позиция, улучшения, cooldown, owner_peer
  и сетевой путь сохраняются (проверено тестом).
- HUD/подпись: «Имя — Берсерка · Волна ярости · Ур. N», NameLabel «• II/III».

## 4. Найденные и исправленные дефекты (в ходе этапа)

1. **Сигнатурная ошибка** `_update_frenzy`: `health_changed(current, maximum)`
   вызывал метод без аргументов → 7 ERROR за прогон. Найдено smoke-прогоном,
   исправлено (аргументы по умолчанию), проверено: 0 ERROR.
2. **Гонка смены сцены в новом коде** (тот же класс, что BUG-2 аудита):
   `_server_shockwave`/комбо-путь получали area-сигнал на пешке вне дерева во
   время реванша → `get_tree()` null → 1 SCRIPT ERROR. Найдено rematch-тестом.
   Исправлено: guards `is_inside_tree()` (shockwave, комбо, `try_evolve_for_level`,
   `_check_evolution`). Перепроверено: rematch PASS, 0 ошибок.
3. **Хрупкая эвристика старого теста** `iron_body > ×1.25`: при формах база HP
   legitimately изменилась (190), накопленные улучшения дали ×1.23 → FAIL без
   реального дефекта. Заменено на более строгую детерминированную проверку:
   макс.HP ТОЧНО = база формы × серверные модификаторы (тест не ослаблен).

## 5. Известные ограничения

- 7 классов — данные+визуал (заглушки): в лобби только Берсерка; статусы и
  очередь — `docs/CLASS_MATRIX.md`. Эволюция других классов дала бы только
  статы/визуал — поэтому до реализации способностей они скрыты (честность ТЗ §20).
- Неистовство — серверные статы; отдельной клиентской подсветки нет, кроме
  локального `set_frenzy` (на сервере); репликация визуального признака —
  с этапом полировки (или через "f"-payload-бит, если потребуется).
- Захваты/броски и разрушение геометрии финальной формы (канон §6.6) — Этап 4
  (физика/командные механики); сейчас волна формы III уже бьёт по ящикам.
- Трансформация — мгновенная с эффектами (кольца/звук/анонс), без анимационной
  кат-сцены: скелетных анимаций нет до подключения `.glb`-моделей (Этап визуала).
- 3–8 игроков автоматикой не проверялись (2 CPU/~1 ГБ — ограничение окружения,
  наследуется из Этапа 2).
