## 3. Что найдено при проверке (и исправлено)

### BUG-1 (тестовый, подтверждён логом)
`tests/smoke_runner.gd`: проба «награда ровно один раз» вручную подключала
`died_on_server` и затем вызывала `_register_enemy()`, который подключает тот же
callable → `ERROR: Signal 'died_on_server' is already connected` в каждом прогоне
smoke. На результаты не влияло (guard `rewards_granted`), но загрязняло лог
настоящей ошибкой. **Исправлено**: удалён дублирующий ручной connect.

### BUG-2 (продуктовый, обнаружен новым rematch-тестом)
Гонка смены сцены при **онлайн-реванше** (и любом выходе в меню во время матча):
клиент ещё шлёт `sv_input` (60 Гц, unreliable_ordered), когда на сервере старая
арена уже выведена из дерева. RPC доставляется узлу вне дерева, где
`multiplayer == null` →
`SCRIPT ERROR: Cannot call method 'get_remote_sender_id' on a null value`.
Уязвимы были 6 обработчиков в сценных узлах:
`PlayerPawn.sv_input`, `PlayerPawn.sv_request_action`,
`MatchController.cl_scene_ready`,
`ProgressionSystem.cl_choose`, `cl_buy`, `cl_wave_ready`.
**Исправлено**: guard `if not is_inside_tree(): return` во всех шести
(семантика верная: узел уничтожается — устаревший RPC игнорируется).
Автолоады (`Net`) не затронуты — они всегда в дереве.

### GAP-1 (покрытие)
Онлайн-реванш не покрывался ни одним автотестом (smoke перезапускает матч только
offline; net-тест завершался после первой победы). **Добавлено**: opt-in режим
`+rematch=1` для `autotest_runner` + скрипт `tests/run_rematch_test.sh`
(те же 2 процесса: полный матч → реванш → второй полный матч; критерий —
2/2 победы + 0 script errors). Поведение существующих тестов не изменено.
Именно этот тест воспроизвёл BUG-2 до фикса (`script_errors=1`) и подтвердил
исправление после (`REMATCH_TEST=PASS`).
